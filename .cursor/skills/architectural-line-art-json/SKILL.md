# Architectural Line-Art JSON

## Назначение

Используй этот skill, когда нужно перенести архитектурный рисунок из SVG в
пошаговый JSON для интерактивного рисования. Результат должен ощущаться как
процесс работы художника: сначала конструктивная схема и большие формы, затем
средние элементы, орнамент и мелкие уточнения.

Главное правило: JSON описывает не просто порядок найденных SVG-path, а
педагогически выстроенный процесс построения изображения.

## Целевой формат

Корневой объект:

```json
{
  "id": "architectural-building",
  "title": "Архитектурный собор",
  "subtitle": "Архитектурный линейный этюд",
  "kicker": "Этюд 03",
  "featured": false,
  "viewBox": "0 0 941 1672",
  "steps": []
}
```

Каждый шаг:

```json
{
  "id": "form-001",
  "name": "Основные формы: цоколь",
  "body": "Собираем нижнюю часть из крупных прямоугольных ярусов.",
  "description": "Крупные горизонтали и вертикали цоколя; без мелких деталей.",
  "duration": 900,
  "paths": [
    {
      "d": "M150 1600H791M205 1450V1170",
      "stroke": "#111111",
      "strokeWidth": 1.35,
      "duration": 900
    }
  ]
}
```

`description` обязателен для содержательных шагов и предназначен для ИИ. Он
должен кратко отвечать на два вопроса: какую часть объекта показывает шаг и
каков его масштаб. Оптимальная длина — 6–14 слов. Не дублируй `body` и не
используй общие фразы вроде «добавляем линии текущей части здания».

## Рабочий процесс

### 1. Зафиксировать систему координат

1. Взять `viewBox` исходного SVG без изменения пропорций.
2. Считать левый верхний угол началом координат.
3. Не отражать и не переворачивать рисунок без явной причины.
4. Все новые конструктивные линии строить в той же системе координат.
5. Проверить, что крайние точки рисунка находятся внутри `viewBox` или
   намеренно выходят за него.

Нельзя подгонять отдельные шаги под экран. Масштабирование и панорамирование
делает viewport, а не данные туториала.

### 2. Исследовать SVG до разбиения

Определи:

- общий габарит объекта;
- центральную ось и симметричные зоны;
- базовую линию и основные горизонтальные уровни;
- крупные объёмы и переходы между ними;
- группы окон, аркад, колонн, орнаментов и мелких деталей;
- порядок, в котором объект логично строится человеком.

Не принимай порядок path в исходном SVG за порядок рисования. Векторный файл
часто оптимизирован для отображения, а не для обучения.

Для fill-path / трассировок сначала разрежь составные path на подконтуры
(`M...`), оцени bbox каждого и только потом группируй. Гигантский общий
силуэт почти всегда нельзя ставить в ранние чёрные шаги.

### 3. Подготовить конструктивную разметку

Разметка должна идти перед чёрным рисунком и иметь отдельные шаги. Она состоит
из простых горизонтальных и вертикальных линий:

- центральная вертикальная ось;
- крайние вертикали общего габарита;
- горизонтальные границы листа или объекта;
- уровни цоколя, ярусов, карнизов и верхней части;
- вертикальные деления ширины крупных объёмов;
- прямоугольные зоны главных проёмов.

Разметка не должна содержать диагональных силуэтов, декоративных кривых или
полного контура башни. Она объясняет масштаб и взаимное положение элементов,
а не подменяет первый этап рисунка.

Для разметки используй:

```json
{
  "stroke": "#A5A5A0",
  "strokeWidth": 1.1,
  "strokeDasharray": "8 8"
}
```

Серые направляющие должны быть визуально слабее чёрного рисунка. Не смешивай
разметку и чёрные path в одном шаге.

### 4. Построить первые чёрные формы

После разметки обязательно начинай с крупных простых форм, а не с единичных
мелких артефактов SVG:

1. большие горизонтальные основания и плиты;
2. вертикальные границы крупных объёмов;
3. основные прямоугольные или осевые ярусы;
4. крупные проёмы и центральные блоки;
5. средние фасадные элементы;
6. малые детали, орнамент и финальные штрихи.

«Снизу вверх» — только ориентир, не жёсткий указ. Главное правило масштаба:
от больших фигур и контуров к мелким деталям. Если верхняя крупная форма
логичнее продолжает уже заданную ось, ставь её раньше мелких деталей нижней
части. Не начинай чёрный рисунок со сверхмелких штрихов только потому, что
они встретились первыми в SVG.

### 5. Держать шаг цельным по ярусу

Один шаг = одна логическая часть объекта на одном уровне. Шаг должен быть
понятным продолжением предыдущего, а не набором линий с разных высот здания.

Жёсткие запреты:

- нельзя в одном шаге смешивать цоколь и шпиль, нижний фасад и верхний ствол;
- нельзя прыгать по ярусам внутри шага;
- нельзя собирать шаг из path, которые рядом только в массиве SVG.

Рекомендуемый порядок после разметки и крупных форм:

1. цоколь / основание;
2. нижний фасад;
3. центральный объём;
4. средний фасад;
5. верхний ствол;
6. шпиль / венчание.

Внутри каждого яруса снова иди от крупного к мелкому. Высокий path, который
пересекает несколько ярусов, относи к доминирующему по перекрытию ярусу, а не
к случайной первой точке `d`.

### 6. Разбить рисунок на шаги

Один шаг должен быть коротким логическим продолжением предыдущего. Разделяй
шаг, если выполняется хотя бы одно условие:

- появляется новый архитектурный ярус;
- меняется масштаб элемента;
- в шаге есть длинная непрерывная линия, которую человек не стал бы рисовать
  одним движением;
- path визуально относится к другой части объекта;
- текущий результат уже выглядит завершённым без следующей группы линий.

Для крупных и средних форм предпочтительно 1–8 связанных path на шаг.
Для большого сложного объекта лучше больше коротких шагов, чем один
перегруженный — но только пока шаг остаётся цельным по ярусу.

Не создавай шаги из случайного набора path. Группа должна иметь визуальный и
учебный смысл.

### 7. Склеивать микродетали, не дробить их

Отдельный шаг на один крошечный штрих почти всегда плох: туториал раздувается,
а прогресс ощущается пустым.

Правила для мелких деталей и финальных штрихов:

- склеивай соседние микроpath внутри одного яруса в группы;
- целевой размер группы: примерно 6–14 path;
- не оставляй шаги с 1–3 микроштрихами, если их можно объединить с соседними
  на том же уровне;
- не склеивай микродетали разных ярусов ради сокращения числа шагов;
- внутри группы сохраняй близкий вертикальный диапазон, без прыжка по фасаду;
- крупные/средние формы не смешивай в одну кучу с микроштрихами.

Если после авторазбиения получилось много одиночных micro-step, сделай
отдельный pass склейки: только `Детали` / `Финальные штрихи`, только тот же
ярус, с лимитом path и лимитом y-span.

### 8. Обращаться с длинными контурами

Не помещай огромный составной контур в первый чёрный шаг. Такой path создаёт
эффект мгновенного обведения всего здания и плохо имитирует ручную работу.

Варианты решения в порядке предпочтения:

1. заменить ранний полный контур крупными горизонтальными и вертикальными
   конструктивными формами;
2. разнести независимые участки контура по архитектурным этапам;
3. разбить длинную линию на геометрически самостоятельные части;
4. оставить полный контур только на позднем этапе, если он действительно
   нужен как финальное уточнение.

Не разрезай кривую посередине без сохранения геометрии. После разбиения каждый
участок должен продолжать предыдущий без скачка, лишней диагонали или
заметного смещения.

### 9. Сохранить привязку к сетке

Сетка и конструктивные линии должны использовать одну систему координат:

- ось должна проходить через реальный центр композиции;
- парные элементы должны иметь одинаковое расстояние до оси;
- горизонтали должны совпадать с реальными уровнями фасада;
- ширины ярусов должны быть согласованы между шагами;
- повторяющиеся элементы должны использовать одинаковый шаг;
- округления координат не должны ломать симметрию.

Для симметричного элемента сначала вычисли одну сторону, затем отрази её
относительно оси. Не подбирай левую и правую координаты независимо.

Разметка в JSON должна быть стабильной при zoom и pan. Не добавляй в данные
экранные координаты, размеры окна или CSS-пиксели.

## Именование и тексты

`name` коротко называет действие и часть объекта:

`body` — понятная подсказка пользователю в 1–2 предложениях. Она объясняет,
что сейчас появляется и почему это продолжает предыдущий шаг.

`description` — машинное описание без лишней мотивации:

```text
Крупные горизонтали и вертикали цоколя; без мелких деталей.
Средний масштаб: симметричные границы оконного яруса.
Мелкий масштаб: короткие линии капителей и орнамента.
Финальное уточнение: малые декоративные элементы верхней части.
```

Не используй в `description`:

- пустые формулировки без части объекта;
- повторение полного `body`;
- оценочные слова;
- инструкции по интерфейсу;
- сведения о скорости анимации.

## Атрибуты path

- `d` хранит исходную геометрию в координатах `viewBox`.
- `stroke` для рисунка обычно `#111111` или `#000000`.
- `strokeWidth` держи единым внутри одного визуального слоя.
- `strokeDasharray` используй только для конструктивной разметки.
- `duration` задавай по сложности и длине линии, а не одинаковым числом
  автоматически.
- `transform` допускается только если он уже нужен для корректной исходной
  геометрии.
- Для line-art используй `fill: none` на уровне рендера и не добавляй заливки
  в tutorial path.

Следи, чтобы закрытые залитые SVG-контуры не превращались в чёрные пятна.
Если исходник содержит fill-path, извлекай или преобразуй только его
контурные линии.

## Проверка результата

Перед завершением проверь:

- JSON валиден и импортируется загрузчиком;
- `viewBox` совпадает с исходным SVG;
- после разметки идут крупные формы, а не случайные мелкие path;
- шаги идут ярус за ярусом, без прыжков по высоте здания;
- каждый шаг логично продолжает предыдущий и целен по одной зоне;
- нет гигантского непрерывного контура на раннем этапе;
- нет серии шагов с 1–3 микроштрихами — мелкие детали склеены группами;
- симметричные элементы привязаны к одной оси;
- серые направляющие отделены от чёрного рисунка;
- `description` конкретен и краток;
- нет лишних полей и шаблонных описаний;
- количество path на шаг не перегружает визуальное восприятие;
- финальные шаги содержат детали текущего яруса, а не новые крупные объёмы.

После изменения запускай typecheck проекта и проверку линтером. Если JSON
собирается, но визуальная последовательность плохая, исправляй порядок и
группировку данных, а не добавляй обходы в рендер-компонент.
